# AI Quest — Spec Compliance Audit

תאריך: 2026-06-23  
לינק חי: https://opal.hai.tech/apps/eduapp/ai-quest/  
סטטוס תשתית חי: `GET /api/health` מחזיר `storage=json`.

## סיכום קצר

המערכת כבר עברה מדמו סטטי למוצר JSON Server עובד:

- שרת Node פעיל.
- שמירה בקבצי JSON.
- תמונות נשמרות ב־uploads.
- API חי תחת `/api`.
- צוותים, submissions ותמונות משותפים בין מכשירים.
- דשבורד מדריך מקבל נתונים מהשרת.

אבל מול האפיון המלא, המערכת עדיין אינה שלמה. היא נמצאת במצב: **Production MVP בסיסי בתהליך השלמה**.

## מה תוקן מתוך ההערות האחרונות

| הערה | סטטוס | פירוט |
|---|---|---|
| מסך חברה נפתח לא טוב | תוקן חלקית | יש מסך משימת חברה מלא במקום פתיחה בתחתית. עדיין כדאי לשפר מידע/למידה לפני המשימה. |
| תיקון מודל לא ברור והודעה נעלמת | תוקן | הודעות נשארות עד סגירה ידנית, בחירת יכולות מוצגת בכרטיסים. |
| לא להציג ציון 100 לתלמידים | תוקן | הוסר `/100` מה־UI ומהפרומפט לתלמיד. מוצגים נקודות, חברות ויכולות. |
| מדריך לא רואה תמונות | תוקן תשתיתית | upload מחזיר `photoUrl`, URL נפתח ב־200, דשבורד מציג thumbnail. |
| שאלות כלליות מדי | לא תוקן עדיין | נשאר שלב נדרש: שאלות חקר אמיתיות לפי חברה. |
| אימות לוגו נכון | חלקי | יש בדיקה ידנית של מדריך תקין/לא תקין. אין זיהוי אוטומטי — לפי האפיון זה עתידי. |

## התאמה לסעיפי האפיון

### 1. תקציר ומטרת פעילות

סטטוס: **חלקי**

קיים:
- פעילות AI Quest.
- צוותים נכנסים עם שפה, שם צוות, קוד אירוע ומשך פעילות.
- איסוף יכולות מחברות.
- מודל AI משתפר לפי יכולות.

חסר/לשיפור:
- הסבר פתיחה עדיין קצר מדי ולא מספיק חינוכי.
- אין עדיין שכבת “למידה על פארק הייטק ואקוסיסטם” מספיק עשירה.

### 2. בעיית מודל ניתנת להגדרה באדמין

סטטוס: **חלקי**

קיים:
- יש `model-problems.json`.
- יש בעיה אחת פעילה.
- אדמין בסיסי יכול לערוך בעיית מודל קיימת.

חסר:
- יצירת בעיות חדשות מלאה.
- הפעלה/הסתרה.
- הגדרת ברירת מחדל לאירוע דרך UI מלא.
- הגדרת required abilities דרך UI.
- הודעות הצלחה/שגיאה לפי בעיה דרך אדמין.

### 3. משכי פעילות 60/90/135

סטטוס: **חלקי**

קיים:
- בחירת משך פעילות בכניסה.
- חלק מהספים משמשים להצגת סיום/צ׳קפוינט.

חסר:
- תנאי צ׳קפוינט מלאים לפי האפיון:
  - 60: אחרי 4 חברות או 3 תחומים.
  - 90: צ׳קפוינט 1 אחרי 3–4, צ׳קפוינט 2 אחרי 6–8.
  - 135: צ׳קפוינטים אחרי 4, 8, 10–12.
- מספר תיקוני מודל נדרש לפי משך.
- מצב פעילות מלא עם 3 צ׳קפוינטים.

### 4. זרימת תלמידים

סטטוס: **בינוני / מתקדם חלקית**

קיים:
- בחירת שפה.
- כניסת צוות.
- סיפור/בעיה.
- רשימת חברות.
- מסך משימת חברה.
- צילום לוגו עם preview.
- שאלות.
- קבלת יכולות.
- תיק מודל.
- תיקון מודל.
- סיום בסיסי עם prompt.

חסר/לשיפור:
- שאלות חקר לא מספיק טובות.
- אין הפרדה מלאה בין “מידע על החברה” לבין “משימת ניקוד”.
- אין פידבק אחרי כל שאלה בנפרד.
- אין מצב “נמצאה אבל לא הושלמה”.
- אין retry ברור להעלאת תמונה.

### 5. חברות, רמות ויכולות

סטטוס: **חלקי**

קיים:
- 12 חברות seed.
- רמות 1/2/3.
- תיאור עברית/ערבית.
- יכולות טכנולוגיות.
- שאלות משויכות לחברות.

חסר:
- כל החברות שהאדמין יזין — יש UI חלקי בלבד.
- הסתרת חברה מאירוע מסוים.
- ניהול יכולות מלא.
- שאלות לפי עומק אמיתי: רמה 1 עם 3 שאלות, רמה 2 עם 2, רמה 3 עם 1.

### 6. שאלות חידון

סטטוס: **חלש / דורש טיפול קרוב**

קיים:
- שאלות אמריקאיות בלבד.
- ניקוד בסיסי.
- תרגום בסיסי.

חסר:
- שאלות ייחודיות ומאתגרות לכל חברה.
- טיפוסי שאלות נוספים: נכון/לא נכון, התאמה, פתוחה קצרה, אתיקה.
- הסבר אחרי תשובה בצורה חווייתית.
- ניהול שאלות באדמין.
- תשובה נכונה לא תמיד במקום ראשון / ערבוב אפשרויות.

### 7. צילום ואימות לוגו

סטטוס: **MVP תקין חלקית**

קיים:
- צילום/העלאה.
- שמירת קובץ בשרת.
- `photoUrl`.
- מדריך רואה thumbnail.
- מדריך יכול לסמן תקין/לא תקין.

חסר:
- התנהגות מלאה כשמדריך מסמן לא תקין:
  - הורדת ניקוד.
  - החזרת חברה לסטטוס “דורש תיקון”.
  - הודעה לצוות “צלמו שוב”.
- אין זיהוי אוטומטי — זה מוגדר באפיון כאפשרות עתידית, לא חובה MVP.

### 8. ניקוד ודירוג

סטטוס: **חלקי**

קיים:
- ניקוד בסיסי על צילום/שאלות/יכולות/תיקון מודל.
- ניקוד לא מבוסס מהירות.

חסר:
- טבלת דירוג סופית.
- בונוס גיוון תחומים מלא.
- בונוס מודל מאוזן.
- ניקוד על הסבר פתוח.
- חישוב איכות הסברים/אתיקה.
- ייצוא ניקוד.

### 9. איכות מודל ותיקון מודל

סטטוס: **בינוני**

קיים:
- חישוב פנימי של איכות מודל.
- הצגת יכולות/חברות/נקודות לתלמידים במקום 100.
- תיקון מודל עם בחירת יכולות.
- הודעות פידבק יציבות.

חסר:
- תיקון לפי תקלות מוגדרות באדמין.
- מספר תיקוני מודל לפי משך פעילות.
- הסבר פדגוגי טוב יותר למה יכולת מתאימה/לא מתאימה.
- חיבור מלא ל־required abilities שהאדמין מגדיר.

### 10. צ׳קפוינטים

סטטוס: **חלקי**

קיים:
- בקשת צ׳קפוינט.
- אישור/דחייה בדשבורד מדריך.

חסר:
- שלושת סוגי הצ׳קפוינט: קוד מדריך, אישור דשבורד, נקודה דיגיטלית.
- תנאים מלאים לפי 60/90/135.
- קוד מדריך בפועל.
- QR/אובייקט דיגיטלי.
- החזרה למשימה/קידום שלב מלא.

### 11. דשבורד מדריך

סטטוס: **בינוני-טוב ל־MVP, לא מלא**

קיים:
- KPI.
- טאבים.
- כרטיסי צוות.
- אישור/דחיית צ׳קפוינט.
- בונוס.
- הודעה לצוות.
- תמונות לבדיקה.
- סימון תמונה תקין/לא תקין.
- זיהוי “תקועים” לפי זמן פעילות.

חסר:
- polling אוטומטי כל 5–10 שניות.
- חיפוש/סינון לפי שם/שפה/סטטוס.
- הודעה לכל הצוותים / לפי שפה / לפי סטטוס.
- איפוס צוות.
- צפייה בתשובות פתוחות.
- פעולה מלאה אחרי סימון צילום לא תקין.

### 12. מערכת אדמין

סטטוס: **חלש / הפער הגדול ביותר כרגע**

קיים:
- עריכת חברות בסיסית.
- עריכת בעיית מודל בסיסית.
- איפוס נתוני runtime.
- חיווי חסר תרגום בסיסי לחברות.

חסר:
- ניהול שאלות מלא.
- ניהול אירועים מלא.
- יצירת חברות חדשה נוחה.
- מחיקה/הסתרה/הפעלה.
- בחירת חברות פעילות לאירוע.
- ניהול משכי פעילות.
- ניהול צ׳קפוינטים.
- ניהול משתמשי מדריך.
- ייצוא תוצאות.
- סטטיסטיקות.

### 13. שפות ו־RTL

סטטוס: **חלקי**

קיים:
- עברית/ערבית בכניסה.
- חלק מהתוכן דינמי דו־לשוני.
- RTL.

חסר:
- לא כל טקסטי UI נמצאים במפת תרגומים.
- חלק מהטקסטים hardcoded בעברית.
- חיווי תרגום חסר לא מלא לכל entities.

### 14. API / JSON Storage

סטטוס: **טוב ל־Production MVP מקומי**

קיים:
- health.
- state.
- event by code.
- event config.
- teams create/get/patch/list.
- submissions upload/list/review.
- checkpoint request/review.
- bonus/message.
- admin companies/model-problems בסיסי.
- uploads.

חסר:
- endpoints מלאים לשאלות.
- events CRUD.
- export.
- instructor dashboard endpoint ייעודי.
- companies get/list נפרדים.
- submissions by team.
- checkpoint code.

### 15. אבטחה והרשאות

סטטוס: **חלש / לא מתאים להפעלה פתוחה ללא בקרה**

קיים:
- לא אוספים מידע אישי מעבר לשם צוות.

חסר:
- אין login למדריך/אדמין.
- אין role separation.
- כל מי שמכיר URL יכול להגיע לאדמין/מדריך.
- אין הגנה על קוד אירוע מעבר לקוד עצמו.
- אין הגבלת גודל/סוג קובץ upload ברמה מספקת.

### 16. דוחות וייצוא

סטטוס: **חסר**

חסר:
- CSV.
- JSON export מסודר.
- Excel.
- תוצאות לפי אירוע.

### 17. ביצועים ועמידות

סטטוס: **לא אומת**

קיים:
- JSON server פשוט.

חסר/סיכון:
- לא נבדק עומס 30–45 צוותים.
- JSON file store עלול להספיק לפעילות קטנה-בינונית, אבל דורש בדיקת עומס.
- אין queue/upload compression.
- אין retry UI.

### 18. בדיקות

סטטוס: **חלקי מאוד**

קיים:
- בדיקת domain בסיסית.
- בדיקות ידניות ל־API/upload.

חסר:
- בדיקות צ׳קפוינט.
- בדיקות ניקוד מלא.
- בדיקות upload/review.
- E2E בעברית/ערבית.
- E2E מדריך מאשר צ׳קפוינט.
- E2E אדמין יוצר שאלה/אירוע.

## שלבי עבודה מומלצים מכאן

### שלב A — השלמת Production MVP להפעלה הקרובה

עדיפות גבוהה מאוד:

1. אדמין שאלות מלא.
2. שאלות חקר אמיתיות לפי חברה, כולל ערבוב תשובות.
3. צ׳קפוינטים לפי משך פעילות.
4. דשבורד מדריך עם polling אוטומטי וחיפוש/סינון.
5. טיפול מלא בסימון תמונה לא תקינה.
6. ייצוא תוצאות CSV/JSON.
7. הגנה בסיסית על מדריך/אדמין באמצעות קוד גישה פשוט.
8. בדיקת עומס בסיסית עם 30–45 צוותים מדומים.

### שלב B — השלמת אדמין ואירועים

1. ניהול אירועים.
2. בחירת חברות פעילות לאירוע.
3. ניהול בעיות מודל מלא.
4. ניהול משכי פעילות וצ׳קפוינטים.
5. חיווי תרגומים חסרים לכל תוכן.

### שלב C — שיפור חוויה חינוכית

1. מסך מידע חברה לפני משימה.
2. שאלות אתיקה/פרטיות.
3. הסבר אחרי כל תשובה.
4. badges ותארים.
5. סיכום צוות עשיר יותר.

### שלב D — אבטחה/יציבות

1. הרשאות אמיתיות.
2. מגבלות upload.
3. גיבוי JSON לפני פעילות.
4. לוג שגיאות.
5. ניטור בסיסי בזמן פעילות.

## המלצה אופרטיבית מיידית

השלב הבא הנכון הוא לא עוד polishing כללי, אלא:

**לבנות אדמין שאלות + לשפר את מאגר השאלות.**

סיבה:
- זו אחת הדרישות הברורות באפיון.
- המשתמש כבר זיהה שהשאלות כלליות מדי.
- בלי זה הפעילות לא תרגיש כמו חקר אמיתי.
- זה גם פותח דרך להזין תוכן אמיתי לפני האירוע.

מיד אחר כך:

1. צ׳קפוינטים לפי משך.
2. Dashboard polling + סינון.
3. Export.
4. קוד גישה למדריך/אדמין.
