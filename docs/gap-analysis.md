## 1. סיכום מנהלים

האפיון המקורי מתאר מערכת פעילות מלאה לשלושה קהלי יעד:

1. צוותי תלמידים במובייל.
2. מדריכים בדשבורד תפעולי בזמן אמת.
3. אדמין לניהול אירועים, חברות, שאלות, בעיות מודל, תרגומים וייצוא.

הגרסה שנבנתה כרגע מממשת את הרעיון המרכזי בלבד:
כניסת צוות, בחירת חברה, שאלות, איסוף יכולות, ניקוד, צ׳קפוינט בסיסי, דשבורד מדריך בסיסי ואדמין בסיסי.

אבל היא עדיין לא עומדת בהגדרת “מוצר שלם” מהאפיון, בעיקר בגלל:

- חוויית תלמיד לא מספיק נכונה ולא מספיק Mobile First.
- בחירת חברה נפתחת בצורה לא נכונה — כרגע כמודאל/אזור בתחתית ולא כזרימת מסך ברורה.
- דשבורד מדריך לא מותאם להפעלה מהירה עם 30–45 צוותים.
- אין backend, אין DB, אין סנכרון אמיתי בין מכשירים.
- אדמין חלקי מאוד.
- אין ניהול אירועים מלא.
- אין שמירת תמונות אמיתית בענן.
- אין הרשאות אמיתיות.

## 4. בעיות UX שזוהו עכשיו

### 4.1 ממשק תלמידים — בחירת חברה

בעיה נוכחית:

- לחיצה על חברה לא מרגישה כמו מעבר למשימה.
- התוכן נפתח בצורה לא מספיק ברורה, ולעיתים בתחושה של “בתחתית העמוד”.
- אין תחושת שלב: מצאתי חברה → מצלמים → עונים → מקבלים יכולת → חוזרים לרשימה.

התנהגות רצויה:

1. לחיצה על חברה פותחת מסך משימה ייעודי או Bottom Sheet מלא־מסך במובייל.
2. במסך המשימה יש כותרת ברורה: שם חברה, תחום, רמה, סטטוס.
3. התהליך מחולק לצעדים:
   - צילום לוגו.
   - שאלות.
   - הסבר קצר.
   - קבלת יכולת.
   - חיבור למודל.
4. בסיום יש מסך הצלחה קצר:
   - “אספתם יכולת: דאטה איכותי”
   - “המודל שלכם השתפר ב־X”
   - כפתור ברור: חזרה לחברות / תיק המודל.
5. אין גלילה מבלבלת למיקום אחר בדף.

### 4.2 דשבורד מדריך

בעיה נוכחית:

- הדשבורד הוא טבלה בסיסית.
- לא מתאים למדריך בשטח עם עומס.
- לא מבליט מי צריך פעולה עכשיו.
- אין תצוגת “תקועים”, “ממתינים לצ׳קפוינט”, “דורשים בדיקת תמונה”.

התנהגות רצויה:

1. Header עם מדדים חיים:
   - צוותים פעילים.
   - ממתינים לצ׳קפוינט.
   - תמונות לבדיקה.
   - צוותים תקועים.
2. חלוקה לטאבים/עמודות פעולה:
   - דורשים אישור עכשיו.
   - צוותים תקועים.
   - כל הצוותים.
   - תמונות לבדיקה.
3. כרטיס צוות במקום טבלה צפופה במובייל/טאבלט.
4. פעולה מהירה לכל צוות:
   - אשר צ׳קפוינט.
   - דחה עם הערה מוכנה.
   - שלח הודעה.
   - הוסף בונוס.
   - סמן צילום לא תקין.
5. חיפוש וסינון לפי שם צוות / שפה / סטטוס.

### 4.3 אדמין

בעיה נוכחית:

- האדמין נראה כמו טופס דמו.
- אין זרימת ניהול מלאה.
- אין ניהול שאלות אמיתי.
- אין ניהול אירועים.

התנהגות רצויה:

- אדמין בנוי לפי מודולים:
  1. אירועים.
  2. חברות.
  3. שאלות.
  4. יכולות.
  5. בעיות מודל.
  6. תרגומים חסרים.
  7. ייצוא נתונים.

## 5. פערי ארכיטקטורה

הקוד כרגע מנסה לשמור על הפרדה בין:

- `domain`
- `data`
- `presentation`

אבל זו עדיין לא ארכיטקטורת מוצר מלאה.

### חסר כדי לעמוד באפיון

1. Backend אמיתי:
   - API לצוותים.
   - API לחברות.
   - API לשאלות.
   - API לצ׳קפוינטים.
   - API לדשבורד מדריך.
   - API לאדמין.

2. Database:
   - events
   - teams
   - companies
   - questions
   - abilities
   - model_problems
   - submissions
   - checkpoints
   - instructor_messages

3. Storage לתמונות:
   - שמירת תמונות לוגו.
   - preview למדריך.
   - סטטוס תקין/לא תקין.

4. Auth/Roles:
   - תלמיד — גישה רק לצוות שלו.
   - מדריך — גישה לאירוע שהוקצה לו.
   - אדמין — גישה לניהול.

5. Realtime / polling:
   - דשבורד מדריך צריך להתעדכן בזמן סביר.

## 6. MVP אמיתי — הגדרה מוצעת מחדש

כדי שהמוצר ירגיש שלם, ה־MVP הבא צריך לכלול לפחות:

### תלמידים

- זרימת onboarding ברורה.
- מסך משימה / חברה תקין במובייל.
- צילום לוגו עם preview.
- שאלות עם פידבק והסבר.
- קבלת יכולת עם אנימציה/חיווי ברור.
- תיק מודל חזותי.
- צ׳קפוינט ברור.
- סיום עם דירוג, חוזקות, חולשות ו־Base44 prompt.

### מדריך

- Dashboard מבוסס כרטיסים ולא רק טבלה.
- תצוגת “דורש פעולה”.
- אישור צ׳קפוינט מהיר.
- בדיקת תמונות.
- שליחת הודעות מוכנות.
- זיהוי צוותים תקועים.

### אדמין

- ניהול חברות מלא.
- ניהול שאלות מלא.
- ניהול אירוע אחד לפחות בצורה מלאה.
- ניהול בעיית מודל אחת לפחות.
- חיווי תרגומים חסרים.

### תשתית

- לפחות backend קל עם DB מקומי/ענני.
- שמירת התקדמות בין מכשירים.
- תמיכה בכמה צוותים במקביל.
- בדיקות בסיסיות לתרחישים המרכזיים.

## 7. Roadmap מומלץ לתיקון

### שלב 1 — תיקון UX קריטי בגרסה הנוכחית

מטרה: לגרום לאב־טיפוס להרגיש נכון יותר גם לפני backend.

משימות:

1. לבנות מחדש את מסך בחירת חברה.
2. להפוך משימת חברה למסך ייעודי / modal מלא־מסך במובייל.
3. להוסיף preview לצילום.
4. להוסיף מסך הצלחה אחרי השלמת חברה.
5. לשפר את תיק המודל כך שיהיה ויזואלי וברור.
6. לבנות מחדש דשבורד מדריך ככרטיסים עם אזורי פעולה.
7. להוסיף סינון: “ממתינים”, “תקועים”, “כל הצוותים”, “תמונות”.

### שלב 2 — השלמת MVP פונקציונלי

1. אדמין שאלות מלא.
2. אדמין אירועים בסיסי.
3. צ׳קפוינט לפי תנאים של 60/90/135 דקות.
4. הודעות מדריך.
5. שיפור תרגומים.
6. בדיקות E2E בסיסיות.

### שלב 3 — מעבר למוצר אמיתי

1. בחירת stack backend.
2. DB.
3. Auth/Roles.
4. Storage לתמונות.
5. Realtime/polling לדשבורד.
6. Export.
7. בדיקות עומס בסיסיות.

## 8. החלטות שצריך לקבל

לפני המשך פיתוח עמוק, צריך לבחור:

1. האם ממשיכים קודם לשפר frontend על בסיס localStorage, או עוברים מיד ל־backend?
2. האם זו אמורה להיות מערכת דמו להצגה, או מערכת שתופעל באמת עם 150 תלמידים?
3. האם יש סטאק מועדף — React/Next/Supabase/Firebase/Base44/אחר?
4. האם צריך login אמיתי למדריכים ואדמין כבר עכשיו?

המלצה מקצועית:

להתחיל בשלב 1 — תיקון UX קריטי — כי הוא יאפשר לך להרגיש את המוצר ולהוסיף הערות מדויקות. מיד אחריו לעבור ל־backend, אחרת הדשבורד והמדריך לעולם לא יהיו אמינים בשטח.

## עדכון מצב אחרי v0.3 — 2026-06-23

בוצע מאז כתיבת המסמך המקורי:

- מעבר מ־localStorage בלבד ל־Node JSON Server.
- API חי תחת `/api` בלינק Opal.
- שמירת צוותים ו־submissions בקבצי JSON.
- Upload תמונות לשרת והצגת thumbnail בדשבורד מדריך.
- מסך חברה מלא במקום פתיחה בתחתית.
- דשבורד מדריך ככרטיסים + KPI + טאבים.
- תיקון מודל עם הודעות שנשארות על המסך.
- הסרת ציון `/100` מתצוגת תלמידים.

פערים מרכזיים שנשארו:

1. אדמין שאלות מלא.
2. שאלות חקר ייחודיות ומאתגרות לכל חברה.
3. צ׳קפוינטים לפי תנאי 60/90/135.
4. פעולות מדריך מתקדמות: polling, חיפוש, הודעות לקבוצות, איפוס צוות.
5. טיפול מלא בסימון צילום לא תקין.
6. ניהול אירועים מלא.
7. ייצוא תוצאות.
8. הגנה בסיסית על מדריך/אדמין.
9. בדיקות עומס ו־E2E.
